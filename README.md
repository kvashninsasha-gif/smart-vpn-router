# foxVPN

VPN-клиент с русским интерфейсом, VLESS/Reality, тёмной темой и правилами маршрутизации.

**Последняя проверенная сборка: 0.1.26 · macOS и Windows · предварительный релиз.** [Все файлы, исходники и SHA256](https://github.com/kvashninsasha-gif/foxVPN/releases/tag/v0.1.26).

Установщик Windows без Authenticode-подписи; Mac без Developer ID/нотарификации. Сервер VPN нужно добавить самостоятельно. Это ещё не полный MVP: [план готовности](docs/readiness-plan.md), [результаты проверки 0.1.26](docs/verification-0.1.26.md).

В 0.1.26 помощник готовит план поддерживаемых сетевых параметров и применяет его после отдельного подтверждения. Добавлены проверка результата, попытка восстановления при ошибке и отдельный возврат настроек в текущем сеансе. Модель объясняет диагностику; настройку выполняет проверенный код приложения. Загрузка модели не требуется для применения плана. [Как пользоваться](docs/local-ai.md).

В 0.1.25 добавлен необязательный локальный ИИ-помощник: отдельная загрузка модели по согласию, объяснение свежей диагностики, отмена и отдельный процесс ответа. Серверы/URI/ключи в модель не передаются. Исправления выполняются проверенными кнопками foxVPN; модель может ошибаться. [Как пользоваться](docs/local-ai.md).

В 0.1.24 полный путь подготовки компонента дополнительно проверен на настоящем подписанном архиве. На MacBook после однократного bootstrap подтверждены совместное обновление приложения/компонента 0.1.23 → 0.1.24 без отдельного PKG новой версии, подключение VPN, HTTPS через туннель и восстановление интернета после отключения. [Системная проверка](docs/verification-0.1.24.md).

В 0.1.23 Mac-приложение и компонент обновляются совместно после одного согласия. Один раз нужно подтвердить переход на новый компонент; дальнейшие обычные встроенные обновления не требуют отдельного установщика и пароля администратора. Запрос Keychain из-за ad-hoc подписи остаётся отдельным ограничением. Подпись/версию архива проверяют GUI и root-сервис, предусмотрен возврат component slot при отказе запуска. Системная приёмка этого перехода отмечается отдельно в отчёте.

В 0.1.22 добавлена защита от повторения отказа DNS: проверка конфигурации до запуска, точная диагностика и обязательные 72 испытания настоящего старта на каждом ядре из готовых сборок. Отчёты с SHA256 находятся в релизе; неуспешная проверка блокирует подписание обновления.

В 0.1.21 исправлен реальный отказ запуска TUN на Mac из-за конфигурации bootstrap DNS. Установленная сборка проверена: туннель, системный DNS и обычный HTTPS через VPN работают; полный системный leak-test остаётся отдельной приёмкой. Кнопка «Обновления» находится в верхней панели всех вкладок. Несохранённые настройки не сбрасываются при фоновых обновлениях; подписки можно редактировать.

## Проверить и настроить

На «Обзоре» и в «Настройках» обеих платформ есть кнопка «Проверить и настроить»: проверяет ядро, серверы и текущее соединение, затем предлагает конкретное действие. Установка компонента macOS и изменение прокси Windows требуют отдельного согласия. Проверка работающего VPN его не прерывает.

## Обновления приложения с подтверждением

С Windows 0.1.20 кнопка «Проверить обновления» доступна на «Обзоре» и в «Настройках», как и на Mac. Приложение проверяет GitHub при запуске, если вы не отключили эту настройку. Скачивание начинается после «Обновить»; установщик проверяется по цифровой подписи и подписанной версии. Перед установкой сохраняется профиль, останавливается VPN и восстанавливается прежний прокси Windows. Установщик показывает прогресс и перезапускает foxVPN.

**Windows 0.1.19 и ниже нужно один раз обновить вручную до 0.1.25:** отключите VPN, закройте прежний foxVPN и запустите новый установщик по кнопке выше. Дальше следующие опубликованные версии будут предлагаться внутри приложения. Подпись обновления проверяется foxVPN и не заменяет Windows Authenticode.

### macOS

В 0.1.7 замена приложения выполняется атомарно с сохранением прежней копии. Выход во время установки блокируется, отмена показывает отдельное состояние, проверка сетевого компонента не блокирует интерфейс.

Сетевой компонент 0.1.7 привязан к владельцу macOS через kernel audit token и
подпись приложения. После установки этой сборки обновите «foxVPN-Network» из
настроек: старый компонент не подтверждает новые возможности. Отключение, выход
и установка обновления требуют подтверждения остановки ядра, DNS и PF. При
отказе связи показывается «Состояние VPN неизвестно», приложение не закрывается
и не заменяется. Изменение владельца через подтверждённый администратором пакет
не переносит старую VPN-сессию в другую учётную запись.

С 0.1.6 foxVPN проверяет отдельный desktop-канал GitHub при запуске и показывает текущую/новую версии. «Обновить» запускает скачивание; «Позже» откладывает до следующего запуска, «Пропустить эту версию» сохраняет отказ только для этой версии. В настройках доступны ручная проверка и отключение проверки при запуске. iOS-релизы не смешиваются с Mac.

Подписанный архив проверяется до отключения VPN и установки. Профиль остаётся в прежнем зашифрованном хранилище; предыдущая `.app` сохраняется рядом, ошибка замены откатывается. После установки foxVPN перезапускается. macOS может отдельно потребовать подтверждение сетевого компонента и доступ к Keychain после изменения локальной подписи.

**Переход с 0.1.5 и более старых версий требует один раз установить актуальную версию вручную:** в старом приложении ещё нет updater. После этого следующие опубликованные Mac-версии предлагаются автоматически. Нужна установленная копия в каталоге с правом записи, например `~/Applications`; запуск из DMG/AppTranslocation не поддерживает замену. Канал содержит предварительные Apple Silicon-сборки, без Developer ID/нотарификации. [Проверки 0.1.7](docs/verification-0.1.7.md), [порядок выпуска обновлений](updates/README.md).

## Что реализовано

- Импорт одной или нескольких VLESS-ссылок: TCP, Reality, TLS, WebSocket, gRPC; проверка UUID, ключа Reality, shortId и несовместимых настроек; устранение дубликатов.
- Ручное добавление, текстовый файл, буфер обмена, импорт QR из изображения и показ QR.
- Список серверов, выбор, удаление, переименование, группы, избранное, фильтры.
- Умный, VPN, Прямой и Пользовательский режимы. `.ru`, `.рф`, `.su` напрямую в Умном режиме. Явные доменные исключения применяются раньше правил зон; `*.example.com` охватывает поддомены, а `example.com` только сам домен.
- Управление отдельным процессом sing-box, проверка конфигурации перед запуском, очистка временных файлов и процесса при отключении.
- Проверка доступности и медианной задержки трёх HTTPS-запросов через изолированный VLESS-прокси, массовая проверка, загрузочный тест 10 МБ, автовыбор по измеренным данным.
- HTTPS-подписки, обычный и Base64-формат, ручное обновление и интервалы 1/6/12/24 часа. Обновление выполняется при отключённом VPN. Повреждённая подписка не заменяет сохранённый список.
- Периодическая проверка соединения и попытка переподключения; перебор доступных резервов при сбое.
- DNS over HTTPS / TLS для прямых и защищаемых доменов, системный DNS при явном отключении защиты; конфигурация перехвата DNS и двух стеков IPv4/IPv6 для TUN.
- Русский интерфейс, меню приложения, меню в трее, Keychain / Credential Manager для ключа шифрования, AES-256-GCM для файла профиля.
- Автозапуск через официальный плагин Tauri, свёрнутый запуск, автоподключение, базовая статистика активного ядра, диагностический журнал с сокрытием ключей.
- Экспорт/импорт переносимой резервной копии JSON. Экспорт конфигурации TUN.

## Существенные ограничения

**В macOS 0.1.5 добавлен отдельный системный компонент TUN и PF Kill Switch.** В настройках нажмите «Установить сетевой компонент», завершите установку в macOS, затем «Проверить компонент» и «Подключить VPN для всего ноутбука». Обычное подключение не требует пароля администратора. Обновление локально подписанного компонента/приложения может потребовать нового подтверждения установки. Старые профили остаются в прежнем режиме до явного включения TUN. Это предварительная сборка; результаты и пределы проверки указаны в [отчёте 0.1.5](docs/verification-0.1.5.md).

Для отдельного локального прокси добавьте свой сервер, нажмите «Подключиться», прочитайте условия и выберите «Подключить локальный прокси». Только это действие переводит профиль в доступный режим без TUN и защиты при обрыве. «Отмена» ничего не меняет. Затем укажите показанный адрес `127.0.0.1:<порт>` как SOCKS5-прокси в нужном приложении. При завершении ядра приложение не гарантирует блокировку трафика, если сторонняя программа умеет переходить к прямому подключению.

В проверке 0.1.3 выполнены HTTPS-запросы через сохранённый удалённый VLESS/Reality-сервер и проверены прямой/VPN маршруты. Это не является проверкой обхода ограничений, утечек DNS или работы TUN в ОС; подробности — в отчёте проверки 0.1.3.

Windows x64 NSIS собран и проверен в GitHub runner; пользовательский ПК остаётся отдельной приёмкой. Intel macOS предусмотрен в исходниках, готовая проверенная Intel-сборка не опубликована. Приложение Apple Silicon не подписано Developer ID и не нотарифицировано.

Значения скорости и задержки не генерируются для демонстрации. Страна сервера не определяется по имени. Полный тест отправки/потерь, GeoIP/GeoSite, маршрутизация приложений, автоматическое обновление ядра, история маршрутов и качества, Multi-VPN пока не реализованы. Полная матрица: [docs/coverage.md](docs/coverage.md).

## Сборка

Требуется Rust stable, Node.js 22+, macOS Command Line Tools и Go 1.25.5 для TUN-ядра, либо Windows MSVC Build Tools и WebView2. Windows системный компонент в этой версии отсутствует.

```sh
python3 scripts/download-core.py
# macOS: отдельное ядро из GPL-исходников со сбросом привилегий
python3 scripts/build-network-core.py --work-dir "$TMPDIR/foxvpn-core-build"
cargo build --release --locked -p smart-vpn-engine --bin foxvpn-helper
cp target/release/foxvpn-helper core/foxvpn-helper
codesign --force --sign - --options runtime --identifier ru.smartvpn.network-helper core/foxvpn-helper
cd apps/desktop
npm ci
npm run tauri -- build --config src-tauri/tauri.macos.conf.json --bundles app
cd ../..
python3 scripts/seal-macos-bundle.py "target/release/bundle/macos/foxVPN.app"
```

На macOS ARM64 готовая `.app` находится в `target/release/bundle/macos/`, на Windows установщик NSIS — в `target/release/bundle/nsis/`. Ядро скачивается отдельно для выбранной ОС с проверкой SHA256 по метаданным официального релиза; при отсутствии опубликованного digest загрузка останавливается.

```sh
# Корневые тесты; SMARTVPN_TEST_CORE обязателен для реальных проверок ядра
SMARTVPN_TEST_CORE="$PWD/core/sing-box" cargo test -p smart-vpn-engine
# По желанию отдельно проверить системный Keychain (создаёт и удаляет тестовую запись)
cargo test -p smart-vpn-engine --test vault_macos -- --include-ignored
cd apps/desktop
npm run build
```

Графический интерфейс работает от обычного пользователя. Root-компонент создаёт интерфейс/DNS и собственный PF anchor; само сетевое ядро после подготовки TUN сбрасывает права до выделенного UID 62077. Если UID занят существующим пользователем, запуск отклоняется. Компонент не отключает весь системный PF и не заменяет чужие правила. При включении защиты очищаются существующие IPv4/IPv6 PF states, поэтому текущие сетевые соединения могут прерваться. Перед тестом не накладывайте несколько активных VPN. Подробнее: [архитектура](docs/architecture.md).

## Структура

`src/` — независимый движок Rust; `apps/desktop/` — интерфейс и команды Tauri; `locales/ru.json` — интерфейс, ошибки, сообщения; `core/` — отдельное ядро и сведения о версии; `tests/` — проверки правил, парсера, шифрования и реального локального VLESS; `docs/` — исходное ТЗ, архитектура и статус; `ci/build.yml` — шаблон сборки платформ для GitHub Actions. Для включения CI скопируйте его в `.github/workflows/build.yml` с доступом GitHub `workflow`; запуск выполняется вручную.

Профиль шифруется в `~/Library/Application Support/ru.smartvpn.router/profile.enc` на macOS, `%APPDATA%/ru.smartvpn.router/profile.enc` на Windows. Ключ находится в хранилище ОС. Не копируйте зашифрованный файл между компьютерами без ключа; для переноса используйте экспорт JSON. Экспортируемые резервные копии и конфигурации содержат секреты и не зашифрованы.

## Обновление 0.1.3 — macOS

Постоянный адрес прокси по умолчанию — `127.0.0.1:2080`; порт можно изменить в настройках при отключённом соединении. Он сохраняется при повторных подключениях и автоматическом восстановлении. Изолированные проверки серверов используют отдельные порты. Занятый порт отклоняется с понятной ошибкой, существующее приложение не останавливается.

Исправлено меню macOS и Command-Q: при выходе завершается ядро, удаляется временная конфигурация и закрывается порт. Завершившееся ядро обнаруживается фоновым циклом и заменяется новым при включённом восстановлении. Большой разрыв времени запускает проверку соединения после возобновления процесса.

Скрытое окно приостанавливает опрос по Page Visibility; запросы не накладываются друг на друга. Обычный опрос передаёт только состояние, порт и запрошенный журнал, а не весь профиль. При отключённом соединении цикл обслуживается реже. Отчёт на MacBook M3: [docs/verification-0.1.3.md](docs/verification-0.1.3.md).

Если macOS спрашивает доступ к Keychain при каждом запуске одной версии, для доверенного foxVPN выберите «Всегда разрешать» в системном диалоге, если такой вариант доступен. Не выбирайте доступ ко всем приложениям. Это решение принимает пользователь на своём Mac; после обновления ad-hoc подписи запрос может появиться вновь.

## Обновление 0.1.5 — системный VPN для macOS

Добавлены установщик локального сетевого компонента, типизированный IPC с проверкой audit token и точного CDHash приложения, TUN IPv4/IPv6, системный DNS и отдельная блокировка PF, которая не зависит от GUI. Ядро работает без root после создания TUN. Компонент отслеживает изменения сети и состояние процесса, восстанавливает подключение и проверяет HTTPS через системный сетевой стек. Перед статусом «Подключено» проверяются и локальный прокси, и обычный системный HTTPS.

В диагностике доступна проверка обрыва на 10 секунд. Она намеренно останавливает ядро; блокировка остаётся, затем компонент восстанавливает соединение. Полное завершение/явное отключение снимает собственные DNS/PF-настройки. Windows WFP-служба, физический сон/пробуждение, полноценные внешние DNS/IPv6/QUIC leak-тесты и остальные недостающие пункты ТЗ не выдаются за проверенные: [матрица](docs/coverage.md).

## Обновление 0.1.11 — сетевой компонент без ложных запросов

Устранён повторный запрос «Обновите сетевой компонент» сразу после его установки. Готовность компонента проверялась одним мгновенным запросом, а установка пакета перезапускает системный демон, поэтому проверка не получала ответ и трактовала это как устаревший компонент; диалог блокировал интерфейс, и подключиться было нельзя. На проверяемом Mac журнал установок зафиксировал две установки компонента 0.1.10 за 13 секунд.

Теперь приложение ждёт подъёма демона (до 10 секунд) и различает устаревшую привязку подписи от перезапуска: переустановка предлагается только в первом случае, а при перезапуске диалог не открывается, интерфейс остаётся доступным и проверка повторяется автоматически. Проверки: [0.1.11](docs/verification-0.1.11.md).

После установки этой сборки macOS один раз попросит подтвердить сетевой компонент, потому что CDHash приложения изменился. Это следствие локальной ad-hoc подписи, а не дефект версии.

## Обновление 0.1.12 — окно компонента закрывается само

После успешной установки сетевого компонента окно «Обновите сетевой компонент» оставалось на экране: приложение не узнавало о завершении системного установщика и пересчитывало состояние только при запуске или по кнопке «Проверить компонент».

Теперь после нажатия «Открыть установщик» приложение ждёт результат, опрашивая состояние каждые 2,5 секунды (до минуты), и закрывает окно само, как только компонент стал актуальным, — сразу после этого можно подключаться. При отмене установки окно возвращается к предложению установить компонент. Проверки: [0.1.12](docs/verification-0.1.12.md).

## Обновление 0.1.13 — сообщение о сбое не зависает

Единственная неудачная проверка при подключении показывала красное сообщение «Не удалось подключиться к серверу», хотя сетевой компонент через несколько секунд поднимал туннель: приложение показывало «Подключено», а сообщение о неудаче оставалось на экране.

Теперь такое сообщение снимается автоматически, как только очередная проверка подтверждает подключение. Проверки: [0.1.13](docs/verification-0.1.13.md).
