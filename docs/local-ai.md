# Локальный помощник foxVPN

В 0.1.25 на «Обзоре», в блоке «Проверка и настройка», появился необязательный локальный ИИ-помощник. Сначала пользователь отдельно подтверждает загрузку модели; затем запускает обычную проверку и нажимает «Объяснить результаты с ИИ». Обычные диагностика и исправления работают без модели.

Используется официальный [Qwen3-0.6B-GGUF](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF), файл Q8_0 размером 639 446 688 байт, лицензия Apache-2.0. Источник закреплён на ревизии `23749fefcc72300e3a2ad315e1317431b06b590a`, SHA256 `9465e63a22add5354d9bb4b99e90117043c7124007664907259bd16d043bb031`. Размер и SHA256 проверяются до сохранения и перед нативным чтением. URL, модель и место сохранения нельзя задавать из WebView. Файл хранится отдельно от приложения в его локальной папке данных `local-ai`; он не увеличивает размер установщика и не скачивается при обычном запуске.

Нативный CPU-движок llama.cpp встроен через закреплённый `llama-cpp-2 = 0.1.159` с отключёнными необязательными возможностями. Ответ выполняется отдельным процессом самого foxVPN, до загрузки профиля, Keychain и Windows proxy recovery. Не используются отдельный HTTP-сервер, Ollama, облачный API или пользовательские исполняемые файлы. Процесс использует максимум четыре CPU-потока, контекст 2048 токенов, ответ до 240 токенов и завершается после ответа. Родитель ограничивает ожидание 90 секундами; отмена/штатный выход завершают дочерний процесс. При принудительном завершении родителя worker отслеживает его исчезновение и также выходит.

## Данные и применение настроек

WebView передаёт для объяснения только идентификатор завершённой backend-проверки. Backend проверяет актуальность состояния и настроек, срок 120 секунд и повторно проверяет актуальность после ответа. Worker получает только фиксированные перечисления, булевы значения и ограниченные счётчики. Названия/адреса/URI серверов, идентификаторы профилей, пароли, ключи, API-токены, журналы и свободный текст диагностических сообщений в модель не передаются. Снимок и ответ не сохраняются на диск. Сетевая загрузка передаёт только запрос публичного файла модели; обработка диагностики не делает сетевых запросов модели.

Модель объясняет результат и не выбирает/не выполняет команды. Проверенный следующий шаг формируется приложением отдельно от текста модели. Выбор сервера, подключение, установка компонента и изменение прокси используют существующие кнопки и подтверждения foxVPN. Ответ отображается как обычный текст; HTML/скрипты/ссылки из него не исполняются. Модель может ошибаться: интерфейс прямо отличает объяснение ИИ от проверенных результатов и действий. Она не создаёт VPN-сервер или ключ доступа, не заменяет системное разрешение macOS и не гарантирует устранение любой проблемы.

- llama-cpp-rs: Utility AI, MIT OR Apache-2.0; используется по MIT, [исходники и лицензии](https://github.com/utilityai/llama-cpp-rs).
- llama.cpp / ggml: MIT, [лицензия](https://github.com/ggml-org/llama.cpp/blob/master/LICENSE).

Полная приёмка Windows на личном ПК, утечки DNS/IPv6, сон/смена сети и сертификаты издателя остаются отдельными задачами. ИИ-помощник не меняет эти границы готовности.

## Сборка из исходников

Для сборки встроенного движка дополнительно нужны CMake, C++-компилятор и libclang. На проверенном Mac использованы Command Line Tools и CMake; `LIBCLANG_PATH` указывает на `/Library/Developer/CommandLineTools/usr/lib`. Это требования к разработчику, готовое приложение не требует установки этих инструментов. На Windows CI используется MSVC/LLVM, `LLAMA_STATIC_CRT=1` и `RUSTFLAGS=-C target-feature=+crt-static`, чтобы клиент не зависел от отдельно установленного C++ runtime.

## Настройка с помощником: 0.1.26

Кнопка «Настроить подключение с помощником» подготавливает план по свежей проверке. Цели: исправление соединения, умная маршрутизация, VPN, задержка и стабильность. Дополнительные параметры позволяют изменить поддерживаемые настройки профиля: маршрутизацию и правила, DNS, порт, восстановление, резервные серверы, стратегию выбора, подключение при запуске приложения, интервалы диагностики/замеров/подписок. На Mac доступны TUN и защита при обрыве; на Windows — локальный прокси и его автоматическая настройка в Windows. Подключение при запуске foxVPN не означает автозапуск приложения при входе в систему.

Модель объясняет диагностику, а план строит и применяет типизированный код приложения. Модель не исполняет команды и не получает ключи доступа. Загрузка модели не требуется для подготовки/применения плана. Пользователь видит конкретные изменения, возможное прерывание соединения и препятствия, затем отдельно подтверждает применение. Устаревший план, неподтверждённое действие, неподдерживаемые параметры и произвольные команды отклоняются. Выбор сервера ограничен успешно измеренными кандидатами текущей проверки, не всеми возможными серверами. Во время активного VPN сохраняется текущий сервер; для сравнения альтернатив сначала отключите его и повторите проверку.

После применения проверяется HTTPS через локальный порт, для автоматического прокси Windows — его адрес, для Mac TUN — состояние компонента/DNS и запрошенная защита при обрыве. Эти проверки не заменяют матрицу утечек и поведения при смене сети. При отказе выполняется попытка остановить новое соединение и восстановить прежний профиль; если остановка не подтверждена, приложение сообщает ошибку и не запускает второе соединение. Отмена пользователем не приводит к самовольному восстановлению подключения поверх нового действия.

С 0.1.27 кнопка возврата сохраняется при переходе между вкладками в текущем запуске приложения. Последующее изменение пользовательской конфигурации или подключения делает возврат недействительным. Данные возврата хранятся в памяти; после перезапуска приложения кнопка недоступна. Помощник не создаёт платный сервер, не получает отсутствующие ключи и не подтверждает системные запросы администратора. Установка отсутствующего сетевого компонента остаётся отдельным действием.

## Уточнения настройки: 0.1.27

Проверка актуальности включает подписки, группы, избранное, названия и параметры серверов. Изменения замеров/счётчиков и отметок обновления подписок не отменяют план; эти данные берутся из актуального профиля при применении/возврате. В подтверждении правил видны домен, старый/новый маршрут и позиции правил, включая добавление и удаление.

На Mac отдельный выбор «Охват подключения» отличает системный VPN от локального прокси. Выбор цели сохраняет явно заданный охват/защиту; переход на системный VPN требует установленного компонента, отключение защиты выбирается явно. Итоговый охват сообщает backend в плане.

«Отменить настройку» отправляет запрос только для текущего идентификатора плана/возврата. Запоздалый запрос не отменяет следующую операцию. Дождитесь окончания текущего сетевого шага и сообщения об отмене/возврате. После подтверждённого завершения применять отмену уже нельзя. При отмене изменённое соединение останавливается; оно не запускается автоматически поверх нового действия пользователя. Аварийное завершение процесса не равно штатной отмене: долговечный журнал настройки ещё не реализован.
