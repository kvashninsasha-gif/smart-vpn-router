**Полный MVP не принят. F01–F05 исправлены в коде 0.1.27 и проверены локально/в UI CI. Следующая работа — защищённое восстановление после аварии/неудачного запуска и приёмка устройств.** Этапы закрываются результатом и доказательствами, а не процентом написанного кода.

## Первый этап — реализация 0.1.27 и критерии дальнейшей приёмки

1. **Убрать потерю сторонних изменений профиля.** Выделить полную ревизию пользовательской конфигурации, включая подписки, избранное и группы. Перед применением/возвратом сравнивать актуальное состояние. Избежать сохранения устаревшей полной копии: безопасно объединять только подтверждённые поля с актуальным профилем либо отклонять любое значимое изменение. Сохранённые метрики и отметки обновления не терять. Приёмка — конкурирующее редактирование/обновление подписки, favorite/group, credential change, автоизмерение, повторное применение/возврат.
2. **Показать настоящие изменения маршрутов.** Структурированный diff добавления/удаления/смены маршрута; домен, старое и новое значение, порядок/приоритет правил, предупреждение при очистке. Одинаковое количество правил не скрывает изменения. Приёмка — пример `example.com vpn → direct` виден в предпросмотре и подтверждении; Unicode/wildcard/5000 правил не ломают окно.
3. **Показать охват соединения.** Для Mac proxy цель не обещает весь трафик; переход на TUN имеет отдельное явное изменение в плане и блокер без компонента. На Windows остаётся явный proxy scope. Приёмка — варианты Mac TUN/proxy, Windows, Direct, отсутствие сервера/компонента; действие и сообщение соответствуют фактическим настройкам.
4. **Объединить состояние операции в интерфейсе.** Прогресс, возможность отмены до необратимого этапа, устранение двойных действий; не терять receipt при переходе вкладок. Не возвращать соединение поверх нового пользовательского намерения. Приёмка — отмена, таймаут, переход вкладки, несохранённый settings draft, параллельное обновление и новые проверки.
5. **Добавить испытания реального пути применения.** Проверить не только Fake Backend, но и настоящий профиль/ядро/проверку HTTP на публичных fixtures; на Windows runner — системный proxy, на Mac — сначала изолированная среда. Предусмотреть отказ save/start/verify/stop/restore и недоступный endpoint. Unit-проба guard не считается доказательством успешного применения на системном VPN.
6. **Выпустить следующую версию после проверок.** Повысить desktop-версию, повторить нужные regression/CI, собрать app/helper/NSIS, подписать исходным ключом, опубликовать новый неизменяемый prerelease. Сверить remote size/SHA256, затем переключить оба feed и кнопки README. Не заменять опубликованные файлы 0.1.26. iOS-версию не повышать при desktop-only работе.

[Три исходных проверочных случая](audits/README.md) — стартовые доказательства. Если выбран безопасный merge вместо глобального отклонения, тесты должны проверять сохранность последних данных, а не навязывать конкретный формат digest.

## Ограничения выполнения и публикации

Для этапов 1–2 доступны исходники, тестовые ядра и runners; разрешение на публикацию уже дано пользователем. Для системных испытаний заранее согласовать окно, когда можно прервать VPN; просьбу отложить личный Windows-ПК сохранить. Пароли/Touch ID/Apple signing подтверждаются только пользователем в системных окнах.

Модель не получает полномочия выполнять произвольные команды ради расширения функций. Её объяснение — вспомогательное; настройку выполняют проверяемые действия приложения с отдельным согласием. Следующий шаг не требует более крупной модели.

Сертификаты издателя и физические устройства — внешние зависимости. GeoIP, multi-VPN, полноценные speed/loss/quality-history не объявлять необходимыми для уже согласованного минимального desktop-пути; системный Windows VPN/Kill Switch, напротив, входят в первоначальный MVP.

Доказательства: [аудит 0.1.26](audit-0.1.26-2026-10-11.md), [окончательные сборки](verification-0.1.26.md), [историческое покрытие исходного ТЗ](coverage.md), [Mac 0.1.24](verification-0.1.24.md), [iOS отдельно](../apps/ios/coverage.md).
