# Аудит foxVPN 0.1.26 — 11.10.2026

Проверено дерево `981e0d0`, код приложения `9008e4d`, опубликованный предварительный релиз 0.1.26. Аудит включает desktop-код, новую настройку с помощником, безопасность IPC/файлов/подписок, обновления, зависимости и соответствие исходному ТЗ. iOS рассмотрена по исходникам и существующим отчётам отдельно от desktop.

**Вывод: продукт остаётся предварительным. Найдены три воспроизводимых недостатка помощника; успешный CI их не покрывает. Полный MVP для Mac и Windows ещё не принят.** Процент готовности не вычислялся: без согласованных весов функций и завершённой системной приёмки он создаёт ложную точность.

Уточнение после аудита: F01–F05 исправлены в коде 0.1.27. [Проверки и статус выпуска](verification-0.1.27.md). Исходные результаты ниже сохранены как исторические доказательства; F06–F11 не объявлены закрытыми.

## Что действительно подтверждено

- Повторно проверены размеры и SHA256 всех 15 assets 0.1.26. Оба живых feed совпали с проверенными JSON; подпись обновления привязана к версии. Публичные файлы не заменялись.
- Три задания CI на коде `9008e4d` успешны: [Windows и установщик](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/38086575235), [интерфейс Windows/macOS](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/38086575232), [macOS core](https://github.com/kvashninsasha-gif/foxVPN/actions/runs/38086575240). Проверки сборки: 133 локальных Rust-теста, 117 Windows workspace-тестов, по 73 UI-теста, 72 старта каждого готового ядра, шесть сценариев модели на каждой платформе. Эти результаты получены при выпуске, полная матрица не запускалась заново в аудите.
- На этом Mac установлен **0.1.24**, компонент тоже **0.1.24**. Новый read-only запрос из установленного подписанного executable подтвердил `connected`, совместимый компонент, живое ядро, активный DNS/Kill Switch, `utun99`, отсутствие сообщения об ошибке. Профиль и Keychain не читались, соединение не останавливалось. Это статус компонента, а не независимое доказательство отсутствия утечек.
- Для новых проверочных случаев вызваны реальные функции `ai::stamp`, `configured`, `build` на публичных данных в памяти: **три теста ожидаемого поведения упали**. После запуска временные изменения исходника полностью удалены. [Патч для воспроизведения](audits/0.1.26-regression-probes.patch), [результат](audits/0.1.26-probes-result.txt), [порядок запуска](audits/README.md).

## Найденные недостатки

Приоритеты: P1 — блокирует обещание полного MVP/надёжного выпуска; P2 — исправить в ближайшем выпуске; P3 — улучшение. Приоритет не является оценкой CVSS или утверждением об удалённой уязвимости.

| ID | Приоритет | Наблюдение и последствие | Доказательство / граница проверки |
| --- | --- | --- | --- |
| F01 | P2 | Свежесть плана не учитывает подписки. План хранит полную старую копию профиля; параллельное изменение только подписки может не отменить план и быть затёрто при сохранении другой настройки | `ai.rs:262–280` исключает subscriptions; `setup_plan.rs:395–400,497–504` сохраняет/пишет копию. Тест добавления подписки оставил stamp прежним. Запись настоящего пользовательского профиля и полный сценарий GUI не выполнялись |
| F02 | P2 | Защита возврата не учитывает избранное/группу сервера. ## Повторная оценка прежних замечаний

| Прежний пункт | Текущий результат |
| --- | --- |
| M1: несовместимый компонент выглядит как сбой сети | Есть протокол 4, различение Stale/Starting/Missing и совместное подписанное обновление app/helper. Переход 0.1.23 → 0.1.24 проверен ранее на Mac. Чужой/старый binding всё ещё намеренно ограничивает управление; отдельная приёмка ручной замены/старого протокола остаётся нужна |
| M2: unwrap в root-демоне | Найденные `unwrap/panic` в `foxvpn-helper.rs` находятся в `cfg(test)`, включая тест отравленного логгера. Старые номера строк не означают открытый production-дефект. Это не доказательство отсутствия всех возможных паник/OOM |
| L3: произвольные пути от WebView | Команды файлов больше не принимают путь. Путь выбирается native Rust-диалогом; чтение ограничено, symlink/reparse отбрасываются. Экспорт создаёт новый файл. Прежний произвольный path-taking IPC устранён |
| L4: подписка может обратиться к localhost/private HTTPS | Проверяются literal IP, результат DNS и каждый redirect; соединение закреплено за проверенными адресами, системный proxy выключен. Прежний обход только через private URL закрыт. Системный DNS lookup до HTTP не имеет собственного прерываемого таймера: задача улучшения таймаутов |
| L1/L2: идентичность/проверка образа | Developer ID отсутствует. IPC берёт kernel audit token, проверяет UID и гостевой SecCode/CDHash, а не просто присланный путь. По текущему коду нельзя повторять старое утверждение «только on-disk образ» без нового доказательства атаки; полноценный pentest не выполнен |
| Остаточные пункты | PF разрешает TCP/UDP UID ядра — часть текущей модели маршрутизации, а не автоматическое доказательство утечки. Сертификаты издателя отсутствуют. Для component slot реализован floor версии/запрет другого архива той же версии. Полный откат GUI и системная матрица остаются открыты |

## Зависимости

11.10.2026 `npm audit` вернул 0 известных уязвимостей. OSV querybatch проверил 566 registry-пакетов Cargo.lock: glib 0.18.5 получил две записи об одном [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html), proc-macro-error 1.0.4 — [RUSTSEC-2024-0370](https://rustsec.org/advisories/RUSTSEC-2024-0370.html) о прекращённой поддержке. Проверка `cargo tree --locked --target ... --edges normal,build` не нашла оба пакета в деревьях aarch64-apple-darwin/x86_64-pc-windows-msvc. Поэтому эти записи не выдаются за найденные уязвимости опубликованных Mac/Windows binaries. В CI стоит добавить регулярную проверку зависимостей с оценкой применимости; необоснованно подавлять все advisory нельзя.

Запросы не являются аудитом нативного C++ llama.cpp, Go-зависимостей закреплённого sing-box, Apple/Windows framework и всех возможных zero-day. Результат описывает известные записи баз на дату запроса.

## Соответствие MVP и следующих версий

| Часть | Реализация | Что осталось до приёмки |
| --- | --- | --- |
| VLESS/Reality, импорт, список, задержка, режимы/исключения | Есть, включая реальные проверки ядра | Сквозные сценарии с реальными серверами каждого транспорта/правила |
| Mac TUN, DNS, Kill Switch | Есть; установленная 0.1.24 отвечает без ошибки | Полная матрица на окончательной версии, включая sleep/network/failure/leaks |
| Windows | NSIS, прокси, автоматическая настройка/восстановление, updater есть | Личный ПК; отдельно системная служба, TUN, DNS, WFP |
| Автозапуск/восстановление/резервы | Есть plugin, intent/backoff, TUN и proxy failover | Перезагрузка, все резервы недоступны, смена сети; ИИ-план не управляет OS autostart |
| Статистика | Общие счётчики и список до 100 активных соединений | Скорости/история; route-поля backend считаются по активному ограниченному списку, их нельзя представлять как пожизненные VPN/direct суммы |
| Резервная копия | Переносимый JSON; plaintext явно указан пользователю | Реальный перенос Mac↔Windows; пароль — опциональное улучшение исходного ТЗ |
| GeoIP/GeoSite, приложения, upload/loss, история качества, независимое обновление ядра | Нет или частично | Отдельные задачи 1.1/1.2, не добавлять их к обязательному MVP задним числом |
| Intel Mac / iPhone | Intel desktop не выпущен; iOS имеет отдельный код/старые сборки | Intel сборка/проверка; iPhone signing/provisioning и физическая VPN-приёмка, затем распространение |

Критическую удалённую эксплуатацию в просмотренных путях не продемонстрировано. Это ограниченный аудит, а не сертификат безопасности. Найденные F01–F11 этим запросом **не исправлялись**: подготовлен [план доработок](readiness-plan.md). Код приложения/подписи/feeds и работающий VPN оставлены прежними; F12 исправлен документацией.
